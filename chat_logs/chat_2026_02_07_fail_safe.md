# 聊天记录 - 2026-02-07 - 极端安全兜底 (Fail-Safe)

## 针对“无法退出弹幕导致电脑无法操作”的终极防御

用户反复强调担心电脑被锁死，这通常是因为透明全屏窗口意外拦截了鼠标输入，或者窗口无法关闭导致遮挡屏幕。为此，我们引入了三道**强制性防线**。

### 1. 看门狗机制 (Watchdog Timer)
*   **文件**: `DanmakuItem.qml`
*   **原理**: 在每个弹幕窗口内部植入一个独立的定时器。
*   **逻辑**: 无论动画是否播放完毕，无论程序逻辑是否卡死，只要时间超过 `duration + 5000ms`（即弹幕飘完后的 5 秒内），该定时器会**强制调用 `destroy()`**。
*   **作用**: 这是最后一道防线。即使动画系统崩溃，或者回调函数失效，弹幕也会在几秒后自动消亡，绝不会永久停留在屏幕上。

### 2. 防御性窗口属性 (Defensive Window Flags)
*   **文件**: `DanmakuWindow.qml` (控制器窗口)
*   **原理**: 尽管该窗口通常不可见 (`visible: false`)，但为了防止逻辑错误导致其意外显示并覆盖全屏，我们显式添加了 `Qt.WindowTransparentForInput` 标志。
*   **作用**: 即使这个全屏控制器窗口意外变成了“可见”状态，它也**绝对无法拦截鼠标**。鼠标点击会直接穿透它到达桌面，确保用户永远不会失去对电脑的控制权。

### 3. 全局联动销毁
*   **逻辑验证**: 确认了 `Main.qml` 中的 `closeAllReminders` 逻辑。当用户点击提醒卡片上的“关闭”或“推迟”按钮时，系统会遍历并强制销毁所有相关的弹幕窗口。
*   **结合**: 配合之前的 `ReminderWindow` 置顶逻辑，确保用户永远可以点击到卡片上的按钮来一键清除所有弹幕。

## 编译与验证
*   执行了 `build_temp.bat`，编译通过。
*   代码逻辑已形成闭环：
    1.  **正常情况**: 弹幕飘完 -> 动画回调 -> destroy。
    2.  **异常情况**: 动画卡死 -> Watchdog -> destroy。
    3.  **极端情况**: 控制器意外显示 -> TransparentForInput -> 鼠标穿透 -> 用户仍可操作电脑。

这套方案从**生命周期管理**（Watchdog）和**系统交互权限**（Window Flags）两个维度，彻底杜绝了“锁死电脑”的可能性。
